## Warum Secure Webhook Token?

Herkömmliche Webhook-Verfahren setzen entweder auf proprietäre HMAC-Header ohne standardisierte Metadaten oder auf generische JWTs, bei denen der HTTP-Request-Body ungeschützt bleibt.

## Entwickelt für autonome KI-Agenten &amp; A2A-Workflows

<CardGrid>
  <Card title="Schutz vor Indirect Prompt Injection" icon="approve-check-circle">
    Da der HTTP-Body kryptographisch über <code>webhook.hash</code> an das signierte Token gebunden ist, können Zwischeninstanzen keine Tool-Ergebnisse manipulieren oder schädliche Prompts einschleusen.
  </Card>
  <Card title="Zustandsloses Reaktives Aufwecken" icon="rocket">
    Schlafende Agenten werden nur geweckt, wenn ein authentisches, nicht abgelaufenes SWT mit verifiziertem <code>iss</code> und <code>aud</code> eintrifft.
  </Card>
  <Card title="Single-Pass Streaming-Verifikation" icon="setting">
    Die Go-<code>swt.Middleware</code> prüft den Body-Hash in einem einzigen Durchlauf via <code>io.TeeReader</code> und stellt <code>r.Body</code> nahtlos für nachfolgende Handler wieder her.
  </Card>
  <Card title="Nahtlose Schlüsselrotation" icon="random">
    Unterstützt <code>kid</code>-Header-Routing und dynamische <code>KeyProvider</code>-Lookups für JWKS- und Multi-Tenant-Rotation.
  </Card>
</CardGrid>

## Ablauf der Request-Verifizierung

<div class="swt-flow not-content">
  <div class="swt-flow-step">
    <div class="swt-flow-num">1</div>
    <h4>Sender berechnet Hash</h4>
    <p>Berechnet <code>sha-256:&lt;hex&gt;</code> über den HTTP-POST-Body und bettet ihn in <code>webhook.hash</code> ein.</p>
  </div>
  <div class="swt-flow-step">
    <div class="swt-flow-num">2</div>
    <h4>Signierter HTTP POST</h4>
    <p>Überträgt das Token via <code>Authorization: Bearer &lt;SWT&gt;</code> über TLS 1.2+ / 1.3.</p>
  </div>
  <div class="swt-flow-step">
    <div class="swt-flow-num">3</div>
    <h4>Signatur &amp; Claims</h4>
    <p>Empfänger prüft Algorithmus-Allowlist, <code>typ: "SWT"</code>, <code>iss</code>, <code>aud</code> und Clock-Skew-Toleranz.</p>
  </div>
  <div class="swt-flow-step">
    <div class="swt-flow-num">4</div>
    <h4>Body-Hash &amp; Replay</h4>
    <p>Prüft den Hash in konstanter Zeit und lehnt bereits verwendete <code>jti</code>-Tokens vor der Verarbeitung ab.</p>
  </div>
</div>

## 30-Sekunden-Schnellstart

<Tabs>
  <TabItem label="Go (v0.5.0)">
    ```go
    opts := &swt.HandlerOptions{
        ExpectedIssuer:   "https://auth.example.com",
        ExpectedAudience: "https://api.example.com/webhooks",
        ClockSkew:        1 * time.Minute,
        ReplayChecker:    swt.NewMemoryReplayChecker(5 * time.Minute),
    }

    mw, err := swt.Middleware(secretKey, opts)
    if err != nil {
        log.Fatal(err)
    }
    http.Handle("/webhook", mw(yourHandler))
    ```
  </TabItem>
  <TabItem label="Node.js / TypeScript">
    ```ts
    const { header, payload } = jwt.verify(token, SECRET_KEY, {
      algorithms: ['HS256'],
      complete: true,
    }) as { header: jwt.JwtHeader; payload: jwt.JwtPayload };
    if (header.typ !== 'SWT') throw new Error('Invalid token type');

    const [, expected] = payload.webhook.hash.split(':');
    const actual = crypto.createHash('sha256').update(rawBody).digest('hex');
    if (!crypto.timingSafeEqual(Buffer.from(actual), Buffer.from(expected))) {
      return res.status(400).json({ error: 'PAYLOAD_MISMATCH' });
    }
    ```
