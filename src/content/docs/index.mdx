## Why Secure Webhook Token?

Traditional webhook schemes either rely on proprietary HMAC headers without standardized metadata, or use generic JWTs that leave the HTTP request body unauthenticated.

## Built for Autonomous AI Agents &amp; A2A Workflows

<CardGrid>
  <Card title="Indirect Prompt Injection Defense" icon="approve-check-circle">
    Because the HTTP body is cryptographically bound via <code>webhook.hash</code>, untrusted intermediaries cannot alter tool results or inject malicious instructions into LLM context windows.
  </Card>
  <Card title="Stateless Reactive Wakeups" icon="rocket">
    Dormant agents wake up only when a valid, unexpired SWT arrives with verified <code>iss</code> (caller) and <code>aud</code> (target agent) claims.
  </Card>
  <Card title="Single-Pass Streaming Verification" icon="setting">
    The Go <code>swt.Middleware</code> verifies the body hash in a single pass via <code>io.TeeReader</code> and restores <code>r.Body</code> seamlessly for downstream handlers.
  </Card>
  <Card title="Zero-Friction Key Rotation" icon="random">
    Supports <code>kid</code> header routing and dynamic <code>KeyProvider</code> lookups for seamless JWKS and multi-tenant secret rotation.
  </Card>
</CardGrid>

## Request Verification Lifecycle

<div class="swt-flow not-content">
  <div class="swt-flow-step">
    <div class="swt-flow-num">1</div>
    <h4>Sender Computes Hash</h4>
    <p>Calculates <code>sha-256:&lt;hex&gt;</code> over the raw HTTP POST body and embeds it into <code>webhook.hash</code>.</p>
  </div>
  <div class="swt-flow-step">
    <div class="swt-flow-num">2</div>
    <h4>Signed HTTP POST</h4>
    <p>Transmits the token via <code>Authorization: Bearer &lt;SWT&gt;</code> over TLS 1.2+ / 1.3.</p>
  </div>
  <div class="swt-flow-step">
    <div class="swt-flow-num">3</div>
    <h4>Signature &amp; Claims</h4>
    <p>Receiver enforces algorithm allowlist, <code>typ: "SWT"</code>, <code>iss</code>, <code>aud</code>, and clock-skew leeway.</p>
  </div>
  <div class="swt-flow-step">
    <div class="swt-flow-num">4</div>
    <h4>Body Hash &amp; Replay</h4>
    <p>Verifies constant-time hash match and rejects reused <code>jti</code> tokens before invoking business logic.</p>
  </div>
</div>

## 30-Second Quickstart

<Tabs>
  <TabItem label="Go (v0.5.0)">
    ```go
    opts := &swt.HandlerOptions{
        ExpectedIssuer:   "https://auth.example.com",
        ExpectedAudience: "https://api.example.com/webhooks",
        ClockSkew:        1 * time.Minute,
        ReplayChecker:    swt.NewMemoryReplayChecker(5 * time.Minute),
    }

    mw, err := swt.Middleware(secretKey, opts)
    if err != nil {
        log.Fatal(err)
    }
    http.Handle("/webhook", mw(yourHandler))
    ```
  </TabItem>
  <TabItem label="Node.js / TypeScript">
    ```ts
    const { header, payload } = jwt.verify(token, SECRET_KEY, {
      algorithms: ['HS256'],
      complete: true,
    }) as { header: jwt.JwtHeader; payload: jwt.JwtPayload };
    if (header.typ !== 'SWT') throw new Error('Invalid token type');

    const [, expected] = payload.webhook.hash.split(':');
    const actual = crypto.createHash('sha256').update(rawBody).digest('hex');
    if (!crypto.timingSafeEqual(Buffer.from(actual), Buffer.from(expected))) {
      return res.status(400).json({ error: 'PAYLOAD_MISMATCH' });
    }
    ```
  </TabItem>
  <TabItem label="Python">

    decoded = jwt.decode(token, SECRET_KEY, algorithms=["HS256"], audience=EXPECTED_AUD)

    if not hmac.compare_digest(actual_hash, expected_hash):
